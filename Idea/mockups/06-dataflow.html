🧠 Why it’s built this way

The request is split into a synchronous core (verify → save item → respond) and asynchronous follow-ups (notify, index, log). This keeps the request path short and makes the extra work independently retryable without holding up the response. The draft → published lifecycle and the activity_log give a clear, reconstructable history of what happened to every item.

⚙️ Sync vs. async at a glance

SYNC Gateway verifies the token & routes
SYNC Items service saves the row
SYNC Response returns to the user
ASYNC Notify followers
ASYNC Update the search index
ASYNC Write the activity log
